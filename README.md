# fail2ban-center

Управление fail2ban на многих серверах из одной веб-панели. На каждом сервере работает агент:
он сам раз в минуту подключается к центру по HTTPS, сообщает о банах и забирает задачи.
Входящий доступ к серверам центру не нужен — подходят хосты за NAT и файрволом.

```
 [сервер + агент] --HTTPS--\
 [сервер + агент] --HTTPS--- [центр: веб-панель, API, SQLite] <-- браузер (HTTPS)
 [сервер + агент] --HTTPS--/          |
                                      +--> Graylog (только чтение логов, по желанию)
```

Банят только джейлы fail2ban на серверах. Центр показывает баны, ставит ручные баны и
разбаны, синхронизирует общий блок-лист между серверами и показывает лог fail2ban.

## Что умеет

- **Баны по джейлам** каждого сервера; ручной бан, разбан, «забанить навсегда» (служебный
  джейл `agent-permanent-ban`, `bantime = -1`), в том числе сразу на всех серверах.
- **Общий блок-лист.** IP, забаненный на одном сервере N раз (порог настраивается), банится на
  всех. Разбан такого IP — вручную на сервере или из панели — снимает его везде.
- **Игнор-листы:** временный (с TTL) и постоянный (дописывается к `ignoreip` сервера, не
  затирая его). Можно списком или файлом.
- **Бан сети Tor:** центр скачивает список exit-нод (по URL, через прокси или из файла) и
  раздаёт его агентам.
- **Лог fail2ban** сервера в панели: с самого сервера или из Graylog.
- **Джейлы находятся сами** на каждом сервере, вводить их не нужно.
- Группы серверов, роли admin/operator, журнал аудита, VPN-сеть (WireGuard) для серверов без
  прямого доступа к центру.

## Быстрый старт

### 1. Центр

```bash
cd center
sudo deploy/install.sh install
```

Спросит порт, интерфейсы (веб-панель и агенты работают на выбранных адресах), создаст свой
CA и сертификат, первого администратора. В конце напечатает адреса `https://…` и **отпечаток
CA** — он нужен при подключении серверов. Подробно — [`center/README.md`](center/README.md).

### 2. Подключить сервер

1. В панели: «Управление агентами» → «Добавить агента», указать имя (лучше — имя хоста).
   Панель покажет токен и готовую команду.
2. На сервере (fail2ban уже установлен и работает), из каталога `agent/` проекта:

   ```bash
   sudo ./install_agent.sh --center-url https://<адрес центра>:<порт> \
       --token <ТОКЕН> --agent-name <ИМЯ> --center-ca-sha256 <ОТПЕЧАТОК>
   ```

Через минуту сервер появится в панели со своими джейлами и банами. Подробно —
[`agent/README.md`](agent/README.md).

### 3. Подключить Graylog (по желанию)

Если лог fail2ban серверов уже собирается в Graylog:

1. В Graylog: пользователь с ролью **Reader**, ему доступ к потоку с логами (Streams → Share →
   Viewer) и токен.
2. В панели центра, «Настройки» → Graylog: URL, токен, поле с именем хоста, фильтр сообщений
   fail2ban → «Проверить подключение».
3. «Настройки» → «Просмотр логов» → «через Graylog».

На серверах ничего ставить не нужно. Подробно — [`center/README.md`](center/README.md#graylog).

## Роли

| Действие | admin | operator |
|---|---|---|
| Просмотр банов, агентов, блок-листа, логов, аудита | ✅ | ✅ |
| Разбан, временный игнор | ✅ | ✅ |
| Ручной бан, бан навсегда, постоянный игнор | ✅ | ❌ |
| Блок-лист, агенты, пользователи, группы, настройки | ✅ | ❌ |

Последнего администратора нельзя удалить или понизить. Вход защищён от перебора.

## Ограничения

- Действие из панели применяется на сервере при следующем чекине — до 60 секунд (интервал
  настраивается). Баны с сервера доходят до центра сразу, через канал уведомлений.
- Баны, временный игнор и блок-лист — только IPv4. Постоянный игнор принимает и IPv6/сети.
- «Забанить навсегда» блокирует тем `banaction`, что настроен в `[DEFAULT]` сервера.
- Центр — один процесс (`gunicorn --workers 1`) и SQLite: десятки–сотни агентов при
  интервале 60 с; около 70 МБ памяти. Агент не резидентен: запускается раз в минуту,
  ~20 МБ на долю секунды.
