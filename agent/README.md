# fail2ban-center agent

Устанавливается на каждый управляемый сервер. Сам стучится исходящим HTTPS в центр (не
наоборот) — входящий доступ к этому хосту центру не нужен вообще. Полное обоснование
архитектуры — `../docs/TZ.md`.

## Требования к хосту

1. **fail2ban уже установлен и запущен** — агент ничего не устанавливает и не настраивает
   джейлы (кроме двух служебных, см. ниже), только подключается к уже работающему
   `fail2ban-server` через `fail2ban-client`.
2. Python 3 (только стандартная библиотека — `pip`/`venv` не нужны).
3. Исходящий HTTPS-доступ к центру.

## Установка

Сначала зарегистрируйте агента в веб-интерфейсе центра («Управление агентами» → «Добавить
агента», или `manage.py add-agent` на центре) — укажите только имя, джейлы не нужны.
Получите токен. Дальше на самом управляемом хосте:

```bash
sudo ./install_agent.sh \
    --center-url https://center.example.org \
    --token <ТОКЕН_С_ЦЕНТРА> \
    --agent-name srv-42
```

Джейлы указывать не нужно — скрипт сам находит их на хосте (`fail2ban-client status`, плюс
реальный `bantime` каждого через `fail2ban-client get`) и записывает в `config.json`;
`agent-permanent-ban` добавляется автоматически и на центре, и здесь. `--jail
имя:bantime_секунд` (можно несколько раз) всё ещё можно передать, если для конкретного
джейла нужен другой bantime, чем реально настроен на хосте — явно заданное значение имеет
приоритет над автообнаруженным; для джейлов, которых `--jail` не упомянул, работает
автообнаружение как обычно.

Если центр поднят со своим внутренним CA — изолированная сеть без публичного DNS-имени,
сертификат не от Let's Encrypt (см. `../center/deploy/generate-internal-ca.sh`) — добавьте
`--center-ca-cert /путь/к/ca.crt` (тот самый `ca.crt` из каталога, который сгенерировал этот
скрипт на центре, не `server.crt`). Без этого HTTPS-чекин будет падать с ошибкой проверки
сертификата — стандартная библиотека Python, которой пользуется агент, доверенные CA не
угадывает, только системное хранилище.

Скрипт:
- создаёт системного пользователя `f2b-agent` (без шелла) — сам процесс агента непривилегирован;
- кладёт `/usr/local/sbin/f2b-agent-helper` (root:root, chmod 700) и
  `/usr/local/sbin/f2b-agent-notify` (root:root, chmod 700);
- находит джейлы хоста и пишет `/etc/f2b-agent/config.json` (URL центра + токен + список
  джейлов, `root:f2b-agent`, chmod 640);
- ставит `/etc/sudoers.d/f2b-agent` — NOPASSWD только на `f2b-agent-helper`, ни на что другое;
- проверяет, что `f2b-agent` реально может выполнить helper через sudo, и сразу
  провижинит служебный джейл `agent-permanent-ban` (bantime=-1, для "забанить навсегда"
  и части сценариев глобального блок-листа), перенося туда же текущий `ignoreip` хоста
  (из `jail.local`), чтобы не было окна без этой защиты до первого успешного чекина;
- ставит и включает `systemd timer` (по умолчанию каждые 60 секунд, см.
  `deploy/f2b-agent-checkin.timer`).

На каждом последующем чекине агент повторяет автообнаружение заново (см. `discover_jails()`
в `f2b-agent-checkin.py`) — если на хосте появился новый джейл или пропал старый, список на
центре само собой пополняется (но не сокращается — за явным удалением исчезнувших джейлов
из списка нужно зайти в панель и нажать «Пересинхронизировать джейлы» на странице агента).

## Что реально делает агент на каждом тике

1. Проверяет/восстанавливает runtime-хук быстрого уведомления о бане на каждом разрешённом
   джейле (`fail2ban-client addaction`, не переживает `restart` fail2ban — самовосстановление
   на каждом чекине, см. §6.1 ТЗ).
2. Опрашивает текущие баны по каждому разрешённому джейлу, считает дифф с прошлым запуском.
3. Один `POST /api/v1/checkin`: отчитывается о выполненных на прошлом тике задачах + дифф,
   получает новые задачи.
4. Выполняет каждую задачу через `sudo f2b-agent-helper <подкоманда>` — **проверяя джейл из
   задачи против своего локального списка, независимо от центра** (вторая граница защиты,
   см. `f2b-agent-checkin.py::execute_task`).
5. Сохраняет состояние на диск **только после успешного round-trip** — при сбое сети
   следующий тик повторит тот же дифф/результаты, ничего не потеряется.

Никакого постоянного демона на хосте нет — `systemd timer` запускает короткоживущий процесс
раз в интервал, не постоянный слушающий сервис.

## Файлы на управляемом хосте

| Путь | Владелец | Права | Назначение |
|---|---|---|---|
| `/usr/local/sbin/f2b-agent-helper` | root:root | 700 | единственное, что реально трогает fail2ban |
| `/usr/local/sbin/f2b-agent-notify` | root:root | 700 | быстрый событийный канал, вызывается самим fail2ban |
| `/etc/f2b-agent/config.json` | root:f2b-agent | 640 | URL центра, токен, разрешённые джейлы |
| `/etc/sudoers.d/f2b-agent` | root:root | 440 | NOPASSWD только на f2b-agent-helper |
| `/opt/f2b-agent/f2b-agent-checkin.py` | root:root | 644 | сам чекин-скрипт |
| `/var/lib/f2b-agent/state.json` | f2b-agent:f2b-agent | 600 | снимок банов + неотправленные результаты задач |
| `/etc/pki/ca-trust/source/anchors/f2b-agent-center-ca.pem` (RHEL/REDOS) или `/usr/local/share/ca-certificates/f2b-agent-center-ca.crt` (Debian/Ubuntu) | root:root | 644 | только если ставили с `--center-ca-cert` — доверенный CA центра |

Плюс два **runtime**-джейла (не персистентные конфиг-файлы, кроме `agent-permanent-ban`,
которая всё же пишет один jail.d-файл — см. ниже): `agent-permanent-ban` (bantime=-1,
провижинится install-скриптом, персистентно — jail.d-файл) и `agent-tor-block` (bantime=-1,
создаётся лениво при первой задаче `tor_sync`, тоже как jail.d-файл — переживает restart).

## Проверка

```bash
sudo systemctl start f2b-agent-checkin.service   # разовый запуск, не дожидаясь таймера
sudo journalctl -u f2b-agent-checkin.service -f
sudo systemctl list-timers f2b-agent-checkin.timer
```

## Отзыв

Отзывается ТОЛЬКО на центре (кнопка «отозвать» / `manage.py revoke-agent`) — следующий
чекин получит 401. Доступ к самому хосту центру не нужен. Полное удаление агента с хоста —
вручную (systemd-юниты, `/etc/f2b-agent`, `/usr/local/sbin/f2b-agent-*`, sudoers-файл,
пользователь `f2b-agent`); отдельного uninstall-скрипта нет.

## Обновление

```bash
sudo install -o root -g root -m 644 f2b-agent-checkin.py /opt/f2b-agent/f2b-agent-checkin.py
sudo install -o root -g root -m 700 f2b-agent-helper.sh /usr/local/sbin/f2b-agent-helper
sudo install -o root -g root -m 700 f2b-agent-notify.py /usr/local/sbin/f2b-agent-notify
```

Перезапуск сервиса не обязателен — таймер запускает новый процесс с нуля на каждом тике,
новая версия подхватится сама на следующем запуске.
