# Агент fail2ban-center

Ставится на каждый сервер с fail2ban. Раз в минуту запускается по systemd-таймеру (на хостах
без systemd — по cron), подключается к центру по HTTPS, сообщает о банах и выполняет задачи
центра. Сам ничего не слушает, входящий доступ к серверу не нужен, веб-сервер не нужен.

## Требования

- fail2ban установлен и запущен. Агент джейлы не настраивает — работает с теми, что есть, плюс
  два своих служебных (см. ниже).
- Python 3.8+ с модулем `ssl` — только стандартная библиотека, pip не нужен. На OpenWrt нужен
  полный `python3` или `python3-openssl`: в `python3-light` модуля `ssl` нет.
- bash; sudo (на хостах с systemd).
- Исходящий доступ к порту центра.

## Подключение сервера

1. В панели центра: «Управление агентами» → «Добавить агента», имя — лучше имя хоста (так оно
   совпадёт с Graylog). Панель покажет токен и команду установки.
2. Скопировать каталог `agent/` проекта на сервер и выполнить:

   ```bash
   sudo ./install_agent.sh --center-url https://<адрес центра>:<порт> \
       --token <ТОКЕН> --agent-name <ИМЯ> --center-ca-sha256 <ОТПЕЧАТОК CA>
   ```

   Без флагов в интерактивном запуске скрипт спросит всё сам.
3. Через минуту сервер появится в панели. Проверить сразу:
   `sudo systemctl start f2b-agent-checkin.service; journalctl -u f2b-agent-checkin -n 20`.

### Флаги

| Флаг | Значение |
|---|---|
| `--center-url` | `https://адрес:порт` центра; адрес должен входить в его сертификат. `http://` не принимается |
| `--token`, `--agent-name` | из панели |
| `--center-ca-sha256` | отпечаток CA центра: скрипт скачает `ca.crt` с центра и примет его только при совпадении |
| `--center-ca-cert <файл>` | вместо отпечатка — `ca.crt`, заранее скопированный с центра (`/etc/fail2ban-center/tls/ca.crt`) |
| `--jail имя:bantime` | необязательно — переопределить `bantime` джейла; джейлы находятся сами |
| `--setup-vpn` | подключение через VPN-сеть центра (WireGuard), только с systemd |
| `--update` | обновить уже установленный агент; с `--center-url`/`--center-ca-sha256` — сменить адрес центра или CA |

Перед установкой скрипт делает настоящий TLS-запрос к центру с проверкой сертификата — если
адреса нет в сертификате или соединение перехватывается, установка остановится с пояснением.
В сертификате — адрес **центра** (из `--center-url`), а не этого хоста: собственный IP агента
туда не входит. Установка нового агента серт центра **не перевыпускает**: если адрес центра
уже в его SAN — ставите и всё; если нужен новый адрес центра — перевыпуск вручную на центре
(`deploy/install.sh configure`, CA тот же), см. `center/README.md` → «HTTPS и сертификат».

## Что ставится

| Путь | Права | Что |
|---|---|---|
| `/opt/f2b-agent/f2b-agent-checkin.py` | root, 644 | агент (один чекин за запуск) |
| `/usr/local/sbin/f2b-agent-helper` | root, 700 | единственное, что трогает fail2ban; каждый аргумент проверяется |
| `/usr/local/sbin/f2b-agent-notify` | root, 700 | отправка мгновенных уведомлений о банах |
| `/etc/f2b-agent/config.json` | root:f2b-agent, 640 | адрес центра, токен, путь к CA |
| `/etc/f2b-agent/center-ca.crt` | root, 644 | CA центра — агент доверяет только ему, не системному хранилищу |
| `/etc/fail2ban/jail.local` | root, 644 | базовый `ignoreip` хоста (переменная `f2b_base_ignoreip` в `[DEFAULT]`); владелец админ, центр не трогает |
| `/etc/sudoers.d/f2b-agent` | root, 440 | `f2b-agent` может запускать без пароля только helper |
| `/var/lib/f2b-agent/state.json` | f2b-agent, 600 | снимок банов и неотправленные результаты |
| `f2b-agent-checkin.{service,timer}` | | чекин раз в 60 с |
| `f2b-agent-notify.{path,service}` | | отправка уведомлений, как только fail2ban записал событие |

Пользователь `f2b-agent` — системный, без шелла. Агент работает от него, к fail2ban обращается
только через `sudo f2b-agent-helper <подкоманда>`.

Служебные джейлы (no-op фильтр, `bantime = -1`):
- `agent-permanent-ban` — «забанить навсегда» и общий блок-лист; файл
  `/etc/fail2ban/jail.d/99-f2b-agent-permanent.local`. В нём же `[DEFAULT]` постоянный
  игнор, собранный подстановкой двух ИМЕНОВАННЫХ переменных:
  `ignoreip = %(f2b_base_ignoreip)s %(f2b_center_ignoreip)s`, где `f2b_base_ignoreip` —
  база хоста из `jail.local` (владелец админ), а `f2b_center_ignoreip` — адреса центра,
  которые этот файл и задаёт (владелец агент). Адреса центра НЕ пишутся сырыми литералами.
- `agent-tor-block` — бан сети Tor; создаётся при первой синхронизации списка.

## Как работает

Каждую минуту агент:
1. Находит джейлы (`fail2ban-client status`) и ставит на них хук уведомлений.
2. Читает текущие баны, считает разницу с прошлым запуском.
3. Отправляет центру `POST /api/v1/checkin`: результаты прошлых задач, новые баны и разбаны,
   новые строки лога fail2ban, список джейлов. В ответ получает задачи.
4. Выполняет задачи через helper. Задачу с джейлом, которого нет на хосте, отклоняет сам,
   даже если её прислал центр.
5. Сохраняет состояние только после успешного обмена — при сбое сети ничего не теряется.

**Мгновенные уведомления.** Хук fail2ban на каждый бан и разбан дописывает строку в
`/run/fail2ban/f2b-agent.events`; `f2b-agent-notify.path` сразу запускает отправку
(`POST /api/v1/event`). Если уведомление не дошло, тот же факт придёт со следующим чекином.

**Остановка и перезапуск fail2ban** не превращаются в «разбаны»: у хука `actionflush = true`,
поэтому при остановке джейла fail2ban не вызывает его на каждый бан, а джейл, который не
удалось прочитать, агент не считает опустевшим.

**Хук живёт только в памяти fail2ban** — после перезапуска fail2ban его восстанавливает
ближайший чекин (до минуты без мгновенных уведомлений; баны всё равно придут с чекином).

## Хосты без systemd (OpenWrt и т. п.)

Установщик определяет это сам. Отличия: агент работает от root по cron раз в минуту (строка
в `/etc/crontabs/root` или `/etc/cron.d/f2b-agent`), без sudo; уведомления отправляются сразу
из хука через `setsid`; файлы агента добавляются в `/etc/sysupgrade.conf`, если он есть;
`--setup-vpn` недоступен. Логи — `logread | grep f2b-agent`. На OpenWrt `/var` в памяти:
после перезагрузки первый чекин сообщит текущие баны заново, центр отбросит дубли.

## Обновление и удаление

```bash
sudo ./install_agent.sh --update          # из каталога agent/ новой версии
```

Отозвать агента — на центре («отозвать» или `manage.py revoke-agent`), следующий чекин
получит 401. Удалить с сервера — вручную: юниты `f2b-agent-*`, `/etc/f2b-agent`,
`/opt/f2b-agent`, `/var/lib/f2b-agent`, `/usr/local/sbin/f2b-agent-*`,
`/etc/sudoers.d/f2b-agent`, пользователь `f2b-agent`, при желании — служебные джейлы
`/etc/fail2ban/jail.d/99-f2b-agent-*.local`.

## На что обратить внимание

- **Антивирус с проверкой HTTPS** (Dr.Web SpIDer Gate и подобные) подменяет сертификат центра,
  агент такое соединение отвергает: `CERTIFICATE_VERIFY_FAILED`. Проверить, кто выдал
  сертификат: `echo | openssl s_client -connect <центр>:<порт> 2>/dev/null | grep issuer=`.
  Исключение для Dr.Web — правило `PASS` (а не `set UnwrapSSL = false`, оно не помогает):

  ```bash
  sudo drweb-ctl cfset LinuxFirewall.RuleSet0 \
      '(proc, dst_address) match ({"/usr/bin/python3.*", "127\.0\.0\.1:8766"}) : PASS' -a
  ```

- **SELinux (РЕД ОС, RHEL)** работает в режиме Enforcing без изменений политики: fail2ban
  только пишет в свой `/run/fail2ban`, а в сеть ходит отдельная служба агента. Напрямую из
  fail2ban (`systemd-run` или соединение с центром) SELinux не пускает.
- **`ignoreip` хоста.** Адреса, с которых вы администрируете сервер, держите в `ignoreip` —
  общий блок-лист банит IP на всех серверах. База хоста — переменная `f2b_base_ignoreip` в
  **`jail.local`** (`[DEFAULT]`): `127.0.0.0/8 ::1` + ваш `ignoreip` на момент установки.
  Она **принадлежит админу** — правьте её там, центр `jail.local` не трогает. Если переменной
  в `jail.local` нет, helper заводит её один раз (при первом синке) и не перезаписывает.
  Постоянный игнор с центра живёт в своей переменной `f2b_center_ignoreip` (в `99-…`), а
  итоговый `ignoreip` = подстановка обеих: `%(f2b_base_ignoreip)s %(f2b_center_ignoreip)s` —
  база никогда не затирается. (Старые установки с `00-f2b-agent-base.local` мигрируют
  автоматически: значение переносится в `jail.local`, файл `00-…` удаляется.)
- **Агент на самом центре** ставится так же, с `--center-url https://127.0.0.1:<порт>`.
